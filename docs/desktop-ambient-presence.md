# mouStache Desktop: ambient presence (subtle but noticeable)

Requirement from the user: the desktop app runs in the background and listens for copy events. It must be **subtle enough not to
distract or block the view**, and **noticeable enough that people don't forget it's there**.

This spec is part of **Phase 2** (capture) in `docs/desktop-roadmap.md`. Build it with the watcher.

## Principles
1. **Never take focus, never block clicks.** Nothing mouStache shows may steal keyboard focus or intercept the mouse.
2. **Glanceable, then gone.** Feedback lasts about a second and fades out. Nothing stays on screen unless the user opens the app.
3. **Quiet by default.** No sounds, no flashing, no notification-centre entries.
4. **Never reveal what was copied.** Feedback shows the *type* (SQL, Command, Image) and not the content, so it is safe on a shared screen or a stream.
5. **Always controllable.** One setting turns the on-screen blip off; another pauses capture entirely. Respect Reduce motion.
6. **Silence about skipped items.** Secrets, password-manager copies and paused apps produce **no feedback at all**.

## Three layers (quietest to loudest)

### 1. Tray / menu-bar icon (always on)
- The moustache mark as a small monochrome icon. macOS: a **template image** (adapts to light/dark menu bar). Windows: light and dark variants chosen from the system theme.
- **States** (the icon itself changes, nothing pops up):
  - *Idle:* static moustache.
  - *Captured:* the moustache "curls" (tips up) for about 600 ms, then returns. Two or three prebuilt frames; no animation library.
  - *Paused:* dimmed, with a small slash. Tooltip says "Paused".
  - *Needs attention:* a small dot (for example macOS Accessibility permission missing, so paste can't work).
- **Tooltip:** `mouStache · 128 items · last: SQL, 2 min ago`.
- Optional (off by default): macOS menu-bar text showing today's count.
- Left click opens the panel. Right click: Open, Pause/Resume, Quick palette, Settings, Launch at login, Quit.

### 2. The "blip" (a tiny on-screen confirmation)
- A small pill, about 200 x 32 px, in the **bottom-right corner of the display that has the mouse**, 16 px above the taskbar/dock edge. Position is a setting (bottom-right, bottom-left, top-right).
- Content: the mini mascot with the **happy** curl, plus `Saved · SQL` (type or tag only; for images `Saved · Image`). 
- Behaviour: fade in 120 ms, hold about 1.2 s, fade out 200 ms. About 85% opaque, no shadow-heavy chrome.
- **Window flags (important):** frameless, transparent, `focusable: false`, shown with `showInactive()`, `setIgnoreMouseEvents(true)` (click-through), `skipTaskbar`, always on top. It must never appear in Alt+Tab or take focus.
- **Coalescing:** a burst of copies updates the same pill (`Saved · 3 items`) instead of stacking. At most one new blip every 2 s.
- **Suppression:** off when the user chose Tray-only or Off; not shown for skipped items (see principle 6); not shown while the user is dragging or typing in the mouStache panel; skipped when the app can detect a fullscreen foreground window (best effort, documented as a limit).
- Reduce motion (system or the existing setting): no slide, just a plain fade.

### 3. Habit nudges (rare and gentle)
- **First run only:** one short message pointing at the tray icon ("mouStache lives here. Pin it so it stays visible").
- The tray tooltip's running count is the daily reminder. No recurring notifications by default.
- Optional (off by default): a weekly "You saved N items, M pinned" system notification.

## Settings (desktop Settings > Presence)
| Setting | Options | Default |
| --- | --- | --- |
| On-screen blip | Off / Tray only / Blip | Blip |
| Blip position | Bottom-right / Bottom-left / Top-right | Bottom-right |
| Blip duration | Short (0.8 s) / Normal (1.2 s) / Long (2 s) | Normal |
| Menu-bar count (macOS) | On / Off | Off |
| Weekly summary | On / Off | Off |
| Pause capture | toggle (also in tray) | Off |

## Files
- `desktop/src/main/tray.ts` (icon states, tooltip, menu), `desktop/src/main/blip.ts` (window + scheduler, pure scheduling logic kept in `blip-scheduler.ts` for tests)
- `desktop/src/renderer/blip.html` + `blip.tsx` (reuses `components/shared/Mascot.tsx`, mood `happy`)
- Tray frames: generated by `scripts/gen-icons.mjs` (add template/dark/light/paused/curl variants, using the shared shape in `lib/brand/moustache.mjs`)
- Settings: new fields in `lib/types.ts` + a Presence group in `components/panel/SettingsSheet.tsx`

## Tests
- **Unit (scheduler):** coalesces bursts, enforces the 2 s limit, respects Off / Tray-only, never schedules for skipped (secret, concealed, paused-app) items, uses the right duration, and the payload contains **no copied text**.
- **Electron e2e:** a simulated capture creates the blip window with `focusable: false` and click-through; it is not the focused window; it hides itself; its text contains the type but not the copied content; a secret copy creates no blip.
- **Manual (Windows, then Mac):** copy in VS Code or Cursor mid-typing: focus stays in the editor, the pill is visible but unobtrusive, Alt+Tab does not list it.

## Known limits
- Detecting a fullscreen or "do not disturb" state is best effort and platform specific, so the blip may still show over some fullscreen games or videos. Users can switch to Tray only.
- Windows can hide new tray icons in the overflow menu until the user pins them; the first-run message explains how.
